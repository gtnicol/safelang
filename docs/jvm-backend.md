# SAFE JVM Bytecode Backend

This document describes the JVM backend (`compiler/jvm/`), the fifth SAFE backend. It compiles a SAFE program directly
to real `.class` bytecode and packages it, together with the SAFE runtime, into a self-contained executable jar that
runs with `java -jar program.jar` and no classpath.

> **CLI invocation.** Examples use a short `safe <subcommand>` form for readability. The actual command is
> `java -jar target/safe-lang-1.0.0-cli.jar <subcommand>`; alias `safe` to that in your shell if you want the
> short form to work literally.

## Commands

| Command                  | Input       | Output     | Description                                     |
|--------------------------|-------------|------------|-------------------------------------------------|
| `safe jvm file.safe`     | Source code | `file.jar` | Compile to a self-contained executable jar      |
| `safe test --jvm tests/` | Test files  | stdout     | Run the SAFE test suite through the JVM backend |

```bash
# Compile to an executable jar and run it standalone
safe jvm examples/fibonacci.safe
java -jar examples/fibonacci.jar

# Run the native test suite through the JVM backend
safe test --jvm tests/
```

The produced jar is fully self-contained: the entry class plus the bundled `io/safelang/**` runtime are written into the
archive with a `Main-Class` manifest, so it needs no classpath and no SAFE installation to run.

---

## Pipeline

```
Source (.safe) → Lexer → Parser → AST
                                    │
                                    ▼
                          JvmCodeGenerator        (AST → bytecode for one class)
                                    │
                                    ▼
                ClassWriter / ConstantPool / MethodEmitter   (serialize .class bytes)
                                    │
                                    ▼
                            JarAssembler          (class + bundled runtime → .jar)
                                    │
                                    ▼
                       Executable jar (java -jar program.jar)
```

CLI wiring: `SafeMain` (`jvm` command) → `SafeRuntime.jvm` → `JvmCompilerService` → `JvmBackend.emit` →
`JvmCodeGenerator` + `JarAssembler`.

## Design Decisions

The backend makes a handful of deliberate choices that explain the shape of the code. They are listed here because each
one constrains how the rest of the backend is written.

### One class, all-static methods

A whole SAFE program compiles to a **single** JVM class. Every SAFE function becomes a `static SAFEValue` method, and
the
top-level statements become the `main` method. There is no instance state and there are no fields — every value flows
through method parameters, locals, and return values. This keeps module linking simple (all functions live in one
namespace) and sidesteps class-layout concerns entirely.

### Every value is a `SAFEValue`

Generated bytecode never works with primitive `int`/`double`/`boolean` for SAFE-level values — everything is an
`io.safelang.runtime.SAFEValue` object reference, exactly like the operand stack of the bytecode VM. Booleans are only
unwrapped to JVM primitives at branch points (via `JvmRuntime.truth`).

### The `JvmRuntime` facade

Generated code never calls `SAFEValue` interface-static factories or arithmetic methods directly. Instead every
operation routes through static methods on `JvmRuntime` — value construction, operators, indexing, builtin dispatch,
contract checks, iteration, and so on. `JvmRuntime` then delegates all semantics to the *existing* SAFE runtime
(`BinaryDispatcher`, `BuiltinRegistration`/`BuiltinExecutors`, the `decreases` measure discipline). This gives two
things at once:

- **Parity for free.** A generated program computes exactly what the interpreter and bytecode VM compute, because they
  share the same runtime code.
- **A simpler constant pool.** Referencing only ordinary class methods (never interface statics) means no
  `InterfaceMethodref` entries are needed, which is part of what lets the class file stay at major version 50.

### Class-file version 50, no `StackMapTable`

`ClassWriter` pins the class-file major version to **50** (Java 6). For major version 50 the JVM falls back to the
**legacy type-inference verifier** when a method has no `StackMapTable` attribute — so the backend emits none, and never
has to hand-compute stack-map frames.

To stay verifiable under the legacy verifier, generated code keeps the **operand stack empty at every branch target**,
and each function has a **single epilogue**: `return` stores the value in a result slot and jumps to one shared exit
that performs the only `areturn`. This guarantees exactly one return instruction and no unreachable code.

> Do **not** raise the version to 51+ without also emitting `StackMapTable` attributes. The split verifier mandated
> by those versions rejects frame-less code.

### Hand-rolled class-file emission

The class-file serializer is written by hand — `ClassWriter`, `ConstantPool`, and `MethodEmitter` — with **no ASM or
BCEL dependency**. This keeps the project dependency-light (the only external runtime dependency is ANTLR).

### Unsupported constructs fail loudly

When the generator meets a construct it cannot compile, it throws `JvmCompileException` rather than emitting silently
wrong bytecode.

## Components

| File                  | Responsibility                                                                                |
|-----------------------|-----------------------------------------------------------------------------------------------|
| `JvmBackend`          | Public entry point. Sanitizes the class name, drives codegen, packages the jar.               |
| `JvmCodeGenerator`    | The compiler: lowers the AST to bytecode for the single class. Handles module/lambda linking. |
| `ClassWriter`         | Serializes a constant pool plus static methods into binary `.class` format (version 50).      |
| `ConstantPool`        | Builds and interns the JVM constant pool (UTF-8, numbers, class/method/field refs).           |
| `MethodEmitter`       | Emits one method's bytecode; tracks `max_stack`/`max_locals`; back-patches forward branches.  |
| `JvmRuntime`          | Static facade called by generated bytecode; delegates all semantics to the SAFE runtime.      |
| `JarAssembler`        | Packages generated classes plus the bundled `io/safelang/**` runtime into an executable jar.  |
| `JvmCompileException` | Thrown for constructs the backend cannot compile.                                             |
| `JvmCompilerService`  | Adapter implementing the shared `SafeCompiler` interface; delegates to `JvmBackend.emit`.     |

### JvmCodeGenerator

The heart of the backend. `generate(ProgramNode)` compiles every top-level function and the `main` method, then drains
a **worklist** of transitively-referenced module functions and a queue of lambda bodies until both are empty. The result
is one class containing the program's functions, every module helper it actually calls, and one `lambda$N` method per
lambda.

It returns the class bytes; `JvmBackend` hands them to `JarAssembler`.

### JvmRuntime

The static facade. Notable groups of methods:

- **Construction:** `integer`, `decimal`, `unsigned`, `text`, `bool`, `nothing`, `list`, `tuple`, `set`, `map`,
  `object`, `enumeration`.
- **Operations:** `binary` (operator dispatch via `BinaryDispatcher`), `not`/`negate`/`complement`, `index`, `field`,
  `store` (nested index assignment), `interpolate`, `equal`, `truth`, `call` (builtin dispatch).
- **Iteration:** `elements`/`hasNext`/`next` (for-in loops), `range`, `bound` (validates while-loop bounds; rejects
  negatives).
- **First-class functions:** `closure` (materialize a lambda value), `invoke` (call-through-value).
- **Contracts:** `requires`, `ensures`, and the `decreases` measure stack (`pushMeasure`/`popMeasure`).
- **Lifecycle:** `program` (register the entry class for lambda dispatch), `arguments`, `setOutput`/`clearOutput` (
  output
  capture for in-process tests), `cleanup` (close file handles at exit).

Builtins are registered once in a static initializer via `BuiltinRegistration.registerAll(...)`, exactly as the other
backends do.

## Module and stdlib linking

The `ModuleRegistry` only indexes the **public** functions and enums of each module. The backend needs private helpers
too, so it gathers everything from `registry.program(module).declarations()` (cached in `JvmCodeGenerator`).

Linking is **on demand**, via a worklist:

1. While compiling a body, each call to a module function is resolved (prefixed `mod:fn` against the registry;
   unprefixed against the current module then builtins) and the target is `enqueue`d under a mangled name
   `module$function`.
2. After the main program is compiled, `generate` drains the worklist, compiling each pending function — public or
   private — into the same class.
3. Module constants, enum variants (including private enums), dotted module access (`math.PI`), and default-parameter
   expressions are resolved the same way, with default-parameter initializers inlined in the **callee's** module
   namespace.

The upshot: only the module code a program actually reaches is compiled into the jar.

## Contracts and `decreases`

Contracts are enforced identically to the other backends, using the shared runtime.

- `requires` runs after arguments are bound, before the body. A false condition throws.
- `ensures` runs after the return value is computed. A false condition throws.
- `decreases(expr)` is enforced with a **per-function measure stack** in `JvmRuntime`. Before the body runs, the measure
  is evaluated and `pushMeasure(name, measure)` checks it is non-negative and **strictly less** than the previous
  measure for that function (if any); a violation throws. On return, `popMeasure(name)` pops it. This mirrors
  `BytecodeVM.decreases` exactly.

No exception tables are emitted: a SAFE trap is terminal (it aborts the program), so generated methods never need to
catch or unwind.

---

## First-class functions

Each lambda is compiled to its own static method, `lambda$N(SAFEValue[] captures, SAFEValue[] args)`. The lambda
captures
all enclosing locals **by value** at the point it is created. A lambda *value* is built with `JvmRuntime.closure`, and a
call-through-value (`f(x)` where `f` holds a function value) dispatches via `JvmRuntime.invoke`, which reflects on the
registered entry class (the lookup is cached). The entry class is registered once at program start via
`JvmRuntime.program`.

---

## The executable jar

`JarAssembler.assemble` writes:

- a manifest whose `Main-Class` is the generated entry class,
- the generated class(es), and
- the SAFE runtime — every `io/safelang/**/*.class` from this backend's own code source (whichever `safe-lang` jar or
  `target/classes` directory is on the running classpath).

The whole `io/safelang/**` tree is bundled. Classes that aren't reached at runtime (e.g. the ANTLR-backed parser) are
simply never loaded, so the absence of ANTLR from the bundle is harmless. The result runs with `java -jar program.jar`
on a stock JRE.

## Parity testing

The backend is verified by **parity**: its output must match the tree-walking interpreter byte-for-byte.

- **`src/test/java/io/safelang/compiler/jvm/JvmCodeGeneratorTests.java`** compiles small programs in-process, loads the
  generated class with a custom `ClassLoader`, invokes `main`, and asserts the captured output equals the interpreter's.
  It covers hello-world I/O, loops with module functions, arithmetic/conditionals, enums and pattern matching, while
  loops with collections and index assignment, multi-module imports, and `requires`/`ensures`/`decreases` (including a
  test that a `decreases` violation traps).
- **`src/test/java/io/safelang/compiler/jvm/JvmClassWriterTests.java`** is a smoke test: it hand-builds a tiny class
  with
  `ClassWriter`/`MethodEmitter`/`ConstantPool`, loads and runs it, proving the JVM verifier accepts the frame-less,
  version-50 bytecode.

Beyond the unit tests, the full SAFE native suite (22 files, 589 assertions in `tests/`) passes **identically** on the
interpreter, bytecode VM, and JVM backends. Run it with `safe test --jvm tests/`; `TestRunnerTests` guards it in-process
on every `mvn test`.
